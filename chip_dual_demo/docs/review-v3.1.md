# v3.1实现审查记录

本次根据用户反馈移除了持久身份资料和登记流程，改为本次通信会话内“芯片1签名、芯片2验签”。

## 已检查事项

- 芯片1为每次通信/重建密钥生成新的签名密钥；芯片2写入对应公钥并执行实际Verify。
- 初始签名通过才进入KEM；KEM完成后芯片1再次签名PK/CT和挑战，芯片2验签后文本密钥才发布。
- 不直接比较K1/K2；两端各自派生并执行双向HMAC确认。
- 重新建钥重新执行签名KeyGen/验签、KEM KeyGen/Encaps/Decaps；旧端点关闭，历史归档。
- 文本记录使用方向分离密钥、派生前缀+序号nonce、AAD报文头、严格序号和重放检查；失败不交付明文。
- 私钥、共享密钥的串口内容和敏感异常执行脱敏，不写入通信JSON。
- 两个模式按钮固定尺寸、以颜色表示当前模式；切换前后根窗口和按钮尺寸不变。
- 通信页使用独立串口变量和刷新接口，不依赖演示页的端口/Var。
- 两种模式共享串口worker互斥，关闭等待两个后台线程完成。

## 仍需现场确认

- 两块真实板的签名KeyGen/签名/验签、签名与KEM配置连续切换、KEM及重新建钥时序。
- 实际固件切换算法配置时密钥槽的清除/保留行为。

模拟测试不能替代上述现场验证。
