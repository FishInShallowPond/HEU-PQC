# v3 独立代码审查

范围：text_crypto.py、workflow.py、text_window.py、gui.py、main.py及新增测试。审查代理只读，没有修改文件或打开COM端口。

第一轮发现并复现：

1. 新建文本会话构造与主会话close并发时，close返回后仍可能发布可用端点。
2. 文本会话重建的归档/替换间隙与export并发时，会导出重复的旧会话。
3. 非预期加密库异常虽然阻止后续发送，但关闭两端与错误审计还不完整。

修复：

- 主会话使用同一_text_lock保护构造、发布、归档、关闭和会话清单快照；锁顺序为_operation_lock → _text_lock → TextExchange锁。
- 两个线程门控回归测试先复现失败，再验证修复。
- 加密库内部异常关闭两端、保存terminal_error；解密内部异常保留已尝试交付的原始/实际报文且received_text=None。界面单独显示“内部异常”，不冒充正确拒绝篡改。
- 超长输入在调用密码库前校验，不消耗nonce、不关闭正常会话。

第二轮结论：上述问题已解决，未发现剩余重要问题或反向锁获取路径。审查代理复跑核心集成与真实Tk文本测试，并进行了额外错误注入检查。

这是针对演示实现的代码审查，不是密码协议安全证明、认证或硬件互操作证据。
