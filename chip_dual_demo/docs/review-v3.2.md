# v3.2实现审查记录

本轮重点仍是数据真实性和图片失败关闭：

- 图片选择/剪贴板内容先做格式、文件大小、像素数和解码验证；远端文件名不直接拼接成本地路径。
- 每个文件块独立AES-GCM认证，文本和文件共用方向序号，避免文件边界导致Nonce重复。
- 接收端必须收到完整结束记录、全部连续块并核对整文件SHA-256后才发布图片。
- 认证失败、重复/缺失/乱序块或摘要错误关闭记录通道，UI不生成缩略图或可下载文件。
- 图片另存从已通过完整性校验的本地附件复制，下载结果保留原始字节。
- 聊天和图片历史不重新编码文件。重键后旧数据字符串和本地已验证附件仍可显示，但旧会话密钥关闭。
- 密钥面板默认掩码和指纹；显式显示/复制仅作用于当前UI。快照和导出不含K或AES密钥。
- 模式按钮固定宽高，仅颜色变化；通信页没有故障演示控件，原先的后端故障测试仍保留在单元测试。
- 通信侧栏使用可拖动分隔条并可整体隐藏；按钮采用两列布局，在1120×780最小窗口和280像素侧栏下重新检查请求宽度，避免文字截断。
- 文本报文明细保留完整原始/实际交付HEX；图片文件记录保留逐块Nonce、头、密文、标签和重组后完整HEX供侧栏检查。逐块完整HEX仅留内存，导出保留摘要，避免16MiB图片产生数十MiB导出膨胀。
- 清空聊天只销毁可见控件与临时附件，不修改`exchange.history`；测试确认审计记录数量不变且仍可导出。
- 复选框统一使用`TickCheckbutton`，选中为`✓`、未选中为空白；算法演示与通信模式均有真实Tk断言。
- 高DPI截图改为直接捕获Tk顶层窗口内容；使用`ImageGrab`按屏幕坐标抓取时曾在窗口超出屏幕范围时得到桌面背景，现保留失败回退但Windows优先使用`PrintWindow`。
- v3.1 EXE已按历史发布SHA-256精确恢复，v3.2使用不同输出文件名继续构建，避免覆盖历史版本。

仍需现场验证真实板端签名、KEM、串口刷新选择及算法配置连续切换。
