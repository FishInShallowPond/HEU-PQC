# LC01 双芯片演示

<!-- impeccable:product-schema 1 -->

## Platform

Windows 桌面，Python 3.13 / Tkinter 8.6；不是网页。

## Stack

本实现选择 Tkinter，真实串口通过 pyserial 3.5 延迟导入。GUI 依赖独立的 workflow 与 profiles 模块，不修改原算法程序。

## Users

根据用户 brief 推断：实验室测试人员与现场演示人员，在两颗 LC01 芯片之间演示密钥封装与数字签名。

## Product Purpose

在同一窗口选择两种模式：算法演示支持13种算法配置、分步/连续芯片流程和完整字段；通信模式提供类似即时通信软件的聊天时间线，支持双向文本和图片，芯片1生成当前会话签名密钥、芯片2实际验签，再使用芯片KEM建立共享密钥和双向确认。图片可在聊天中查看、下载或用Ctrl+V粘贴到发送区。

## Operating Context

默认真实硬件。流程模拟必须由用户显式启用，并持续显示醒目标识；模拟仅验证流程与界面，不能证明密码算法正确。初次单步执行初始化，初始化后可继续单步或一键运行剩余步骤。

## Capabilities and Constraints

- 字段是 core 提供的正常序 bytes，显示完整大写 HEX，不二次反转、不截断、不改变消息。
- 签名消息支持 UTF-8 与 HEX，长度必须为 1..1000 字节且不是 8 的倍数。
- 后台线程执行 core，主线程经队列更新 Tk。操作期间禁止并发；现有会话配置保持锁定，断开后才能修改。
- 停止请求在当前步骤结束后生效（一步可能包含多个命令）；关闭窗口等待工作线程及串口释放。
- 导出由 `DemoSession.export(Path)` 实现，GUI 展示其实际返回目录。
- 通信模式不创建或保存身份资料。芯片1本次签名公钥只用于本会话和本次KEM绑定，不提供跨会话长期身份识别。
- 通信模式没有单步操作，不直接比较K1/K2；重新建钥必须重新执行芯片1签名KeyGen/验签、KEM KeyGen/Encaps/Decaps和签名绑定。
- 通信模式独立拥有串口选择、刷新、波特率和超时设置；模式按钮固定尺寸，只改变当前颜色，窗口不因切换模式改变大小。
- 图片保留原始字节，按64KiB分块认证加密；单文件不超过16MiB、32兆像素，只在全部分块和整文件SHA-256通过后显示。
- 聊天右侧是可拖动调宽、可整体隐藏的侧栏，包含K(A端)、K(B端)、A→B/B→A AES密钥的掩码和指纹，以及可逐条查看的密文/报文明细。可显式勾选显示完整密钥并复制，导出仍不包含密钥。
- 指纹是密钥原始字节的SHA-256摘要（64位大写HEX），用于比较，不是密钥本身。
- “清空聊天”只清理可见聊天及临时附件；底层加密审计记录保留，仍可导出。
- 通信导出隐藏SK/K及派生密钥，只保留公开会话数据、文件元数据/哈希、报文、有效响应、脱敏字节计数和拒绝原因；界面“显示完整密钥”不会改变导出内容。
- 字段、步骤与结果的唯一依据是 `docs/design.md` 的 core 接口与事件。

## Defaults

来自接口设计：COM5 / COM6，波特率 38580，读取超时 0.2 s，命令超时 20 s，命令间隔 0.08 s，消息 `HEU dual chip demo`。GUI 默认选择 kyber512（若字典缺失该键，则选择首个 profile）。默认窗口 1320×900，最小 1120×780。用户可编辑端口、波特率与命令超时；其余使用 core 默认值。

## Brand Commitments

本实现根据实验室演示场景采用中文、浅色实验室风格。绿色表示通过，红色表示失败，文字同时表达状态。技术字段可滚动、可键盘全选及完整复制。

## Evidence on Hand

`docs/design.md`、`docs/v3.2-design.md` 提供 API、事件与协议边界。真实硬件效果需要接入两块芯片后确认；固件连续切换签名/KEM配置也需现场验证，不虚构硬件实测结果。

## 故障演示（v2）

支持发送前暂停、等长HEX手改和按字节偏移/XOR翻转公钥、密文、签名或消息的发送副本。原始输出始终保留；已发送历史只读。两颗芯片分别显示原始生成值和接收/输入数据，默认联动页签并逐字节红色比较。字节差异不阻断运算；K不一致和合法验签失败作为实际结果完成。传输输入明确为已下发并获响应的上位机记录，不冒充硬件读回。日志导出区分串口写入状态和响应确认状态。
