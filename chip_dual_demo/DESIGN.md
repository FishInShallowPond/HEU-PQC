# 双芯片桌面界面设计

## 方向与用途

Operate：明亮实验室中的双芯片操作台。布局由实际两路芯片与传输方向决定；初屏即可找到配置、下一步、完整字段和结果。遵循用户明确 brief，直接采用代码实现，不额外创建技能配置、网页或图片资产。

主窗口顶部采用两个固定尺寸模式按钮“算法演示”与“文本加密通信”，当前模式只改变背景/文字颜色，不改变窗口或按钮几何。切换模式时自动释放另一模式空闲会话；任一模式有后台工作时禁止切换，避免两模式同时占用串口。界面不显示版本号。

## 布局

- 顶部中文标题与硬件／模拟模式标识，模拟为持续可见的琥珀色标签。
- 配置区显示 profile 名称与 family、两路 COM、波特率、命令超时、模拟开关与串口刷新。签名算法显示 UTF-8／HEX 消息输入和实际字节数。
- 操作栏按连接初始化、单步、一键运行、停止、断开、导出排列。右侧显示当前连接与执行状态。
- 主工作区左右分别属于芯片1、芯片2，中间绘制传输箭头，展示中文步骤、进度及绿／红结果。字段用页签组织，每个字段独立保留完整内容、实际长度和复制按钮。
- 底部显示实时通信日志。主区／日志可拖动分隔；字段和日志支持滚动，最小窗口仍可读取完整数据。

## 视觉规则

背景 #F3F6F8，数据面 #FFFFFF，正文 #182D3D，辅助字 #526775，分隔 #CDD8E0，主操作 #135C75，通过 #176443，失败 #A52A32，模拟 #805000 / #FFF1CB。用浅底与细分隔形成层级，不添加装饰渐变、阴影或伪造指标。

界面使用 Microsoft YaHei UI；仅 HEX、长度与日志采用 Consolas。标题 20 pt，区标题 12 pt，正文 10 pt，HEX 11 pt。控件留有键盘焦点反馈，禁用态不可触发操作；状态除颜色外总有中文文字。

## 交互与线程

GUI 只消费 core 的 log、field、step、result 事件。工作线程仅做 core 和串口枚举，事件进 Queue；所有控件、变量、剪贴板与对话框均在 Tk 主线程访问。每次只有一个后台任务，配置在整个会话期间冻结，断开释放会话引用后恢复。

连接按钮调用首次 `step()` 完成初始化；单步调用 `step()`；一键调用 `run()` 执行剩余。停止调用 core `stop()`，界面显示等待当前步骤结束（一步可能包含多个命令）；不强杀线程。关闭窗口先请求停止，再等待工作线程结束并在线程中关闭会话，最后销毁窗口。

显示与复制均使用 core 给出的正常序 bytes 的大写 HEX；换行只是 Text 的视觉折行。空数据有明确空态。异常保留已接收字段和日志，显示原因及断开重连提示。导出使用实际返回路径。

## 验证边界

v2补充：工具栏提供“篡改 / 对比”，模式区提供发送前暂停开关。编辑任务使用保护焦点的独立窗口，左侧为原始正常序HEX，右侧为等长编辑副本；按字节标红并显示差异数量/从0开始的偏移。主界面增加双侧输入页签、自动对端联动及默认差异高亮，False结果仍正常完成并显示篡改后的实际结果。已确认的输入只读，未确认输入不伪装成芯片读回。

`python -B main.py --smoke-test` 隐藏窗口，通过实际 Tk 事件循环运行模拟 KEM、签名、文本和图片流程，核对控件、文件哈希和界面状态。Pillow同时用于运行时的图片校验、缩略图及Ctrl+V剪贴板粘贴；`--screenshot PATH` 使用其截图入口。模拟通过不等于硬件算法通过。

通信页采用聊天式布局：上部为统一消息时间线，下部固定输入框；右侧独立显示连接设置、当前密钥和报文明细。右侧栏使用可拖动分隔线调整宽度，并可整体隐藏/显示；连接操作采用两列按钮，窄侧栏仍显示完整文字。支持A/B发送身份、图片附件预览、Ctrl+V粘贴、接收缩略图、查看和另存；“清空聊天”仅清除可见消息与临时附件，底层审计记录保留。复选框使用明确 `✓`，未选中为空白。页面拥有独立的签名与KEM算法、芯片1/2串口、刷新串口、波特率和命令超时。用户界面不包含故障注入或重放按钮。
