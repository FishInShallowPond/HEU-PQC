# LC01 Secure Link

独立双设备安全通信程序，首个可执行版本 **v0**。原 `chip_dual_demo` 的 v3.1/v3.2 保留；本项目不覆盖旧演示程序。

两台 Windows 10/11 x64 电脑在同一局域网，各控制自己的 LC01 板。A 监听、B 连接，通过双方签名、KEM、密钥确认建立会话，再进行双向 AES-256-GCM 文本和文件通信。图片作为原始文件传输，接收后可用系统图片查看器打开。v0 是新的轻量原生程序，不依赖 Python。

## 运行

将整个 `bin` 文件夹分别复制到两台电脑，保留 EXE 旁边的 `libcrypto-3-x64.dll` 和许可证。运行 `LC01_Secure_Link_v0.exe`。

1. A 选择监听角色；B 选择连接角色，填写 A 的局域网 IPv4 地址，两边 TCP 端口相同。v0 一次连接一个对端。
2. 每端分别刷新并选择本机连接 LC01 的 COM 口，默认波特率 38580。两边使用相同模式。无板时可明确选择“软件验证”，此时使用真实软件 PQC，不访问串口。
3. A 开始监听，B 连接。Windows 防火墙首次提示时按实际网络环境允许局域网访问。
4. 双方签名与共享秘密确认完成后，两边显示完整的 64 位 HEX 会话指纹。通过面对面或已有可信的独立渠道核对完整指纹，在两端确认一致，才会开放业务通信。发现不一致应拒绝并断开。
5. 在聊天记录下方输入文本发送，或选择图片/其他文件发送。界面区分本机发送与对端接收确认。单文件上限 16 MiB，按约 4 KiB 块流式处理。默认接收目录为 `%LOCALAPPDATA%\LC01_Secure_Link\Received`，可在未连接时改为其他目录。
6. 可请求重新建钥；文件传输期间先完成传输。重新握手后再次核对指纹。断开或失败后重新连接建立全新会话。

“签名有效”证明发送者掌握当前公钥对应的私钥；临时收到的公钥本身无法说明对方是谁。v0 不建立身份登记资料，通过独立渠道核对本次握手指纹来建立本次会话的对端信任。仅在聊天网络上传递或对照指纹不具备这一保证。后续无人值守部署需要可信预置公钥、证书或其他经过设计的信任机制。

## 模式与验证边界

| 模式 | 签名 / KEM | 数据来源 | 当前验证含义 |
|---|---|---|---|
| LC01 硬件 | 固件 Dilithium2 / Kyber512 | 本端串口实际响应 | 驱动已实现；真实双板连续切换及互通需现场验证 |
| 软件验证 | OpenSSL ML-DSA-44 / ML-KEM-512 | 各端独立软件密码运算 | 可验证签名、KEM、握手与应用协议；不代表硬件通过 |

两种模式有不同的握手模式标识，不互通、不静默降级。不能因为部分字段长度相同就把固件旧算法等同于标准 ML-DSA/ML-KEM。本项目不实现 QKD，也没有 QKD 验证结果。

网络只发送公钥、挑战、KEM 密文、签名、确认消息和加密业务记录；不发送私钥、原始共享秘密或业务密钥。这里采用项目自定义的演示握手/记录协议，**不是 TLS、SPDM，也不是已经审计认证的安全通信产品**。

## 实现与 MCU 替换

| 层 | 当前实现 | 后续硬件替换位置 |
|---|---|---|
| 会话与记录 | `src/session.c`，C99，显式缓冲区和严格状态 | 保留协议接口；针对目标 MCU 缩减缓冲区并验证栈空间 |
| 芯片后端 | `src/chip_win32.c`，本地单 COM、超时和取消 | 换成 MCU UART/SPI 等经过确认的实际 LC01 接口驱动 |
| 密码原语 | `src/crypto_openssl.c`，成熟 EVP API | 适配 Mbed TLS/PSA 或经验证的 MCU 加速后端 |
| 网络与文件 | WinSock / Win32，流式分块、有界命令队列 | lwIP/RTOS、存储或分块回调；按链路 MTU 配置 |
| 人机界面 | 原生 Unicode Win32 窗口 | 可保留电脑作为控制显示端，或改为设备界面 |

媒体不通过 LC01 的控制串口。MCU 直接与 LC01 连接能够去掉 PC/USB 串口路径中的部分开销；总时间仍由实际带宽、固件计算、命令次数和等待决定，不能先承诺“极大降低”的数值。v0 未移植到 MCU，未测能耗，也未证明综合指标优于商用产品。握手临时缓冲区、OpenSSL 内存和 Win32 线程栈都必须计入测量，4 KiB 分块并不代表整个程序仅占 4 KiB RAM。

## 构建与测试

开发环境使用 MSYS2 UCRT64 的 GCC、CMake、Ninja、OpenSSL 3.5+（当前打包后端版本见验证记录）。默认工具链路径可修改或通过参数提供：

```powershell
.\build.ps1 -ToolchainRoot 'D:\Config Files\MSYS2\ucrt64'
.\bin\LC01_Secure_Link_v0.exe --self-test
.\bin\LC01_Secure_Link_v0.exe --gui-smoke
.\tests\run_integration.ps1 -Exe .\build\test_endpoint.exe
```

`test_endpoint` 是构建目录中的无窗口自动测试入口，测试端自动确认指纹，仅用于本机回环自测；正常 GUI 始终要求人工确认。单元测试验证密码已知答案、真实软件 PQC、串口帧与记录拒绝路径；双进程测试验证彼此独立的端点。具体结果以 [验证记录](docs/verification-v0.md) 为准。

密码后端接口参考 [OpenSSL ML-DSA 文档](https://docs.openssl.org/3.6/man7/EVP_PKEY-ML-DSA/) 与 [OpenSSL ML-KEM 文档](https://docs.openssl.org/3.6/man7/EVP_PKEY-ML-KEM/)。OpenSSL 许可证随程序分发。
