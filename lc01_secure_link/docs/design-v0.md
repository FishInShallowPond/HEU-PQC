# LC01 Secure Link v0

2026-11-04；已获授权的新程序实现范围，独立于chip_dual_demo。

双Windows端各接一块LC01，A监听、B连接，双方签名验签、A生成KEM密钥、B封装、A解封装，各自HKDF派生方向密钥，完成绑定握手的HMAC确认后，双方人工核对完整会话指纹并确认，才允许聊天。会话公钥为临时公钥，指纹通过面对面/可信独立渠道核对；不称为长期设备身份，不设身份登记文件。指纹覆盖双方角色、公钥、挑战、KEM PK/CT及签名。确认前禁止业务明文发送。

C99协议与业务核心；Windows原生Unicode窗口、WinSock、Win32串口；成熟OpenSSL密码后端。软件验证模式使用真实ML-DSA-44/ML-KEM-512，仅供无板验证；硬件模式使用既有LC01 Dilithium2/Kyber512原始命令，二者算法标识不同，不自动互通/回退，不宣称旧芯片为标准ML算法。

v0使用明确标识的研究演示握手与AES-256-GCM记录协议，不冒称TLS或SPDM。OpenSSL作为密码原语后端，后续可替换MCU密码库；核心不依赖Python/Tk，GUI和硬件/网络驱动在适配层。固定4KiB业务块、有界队列，文件流式读写，完整结束和SHA-256通过后commit；认证失败不发布数据。无真实MCU能耗/硬件互通承诺。

每条连接一个工作线程，所有UI更新通过事件队列；握手等待人工确认可取消。双方签名绑定完整KEM上下文；签名失败、模式不符、错误长度、超时、序号/方向/会话不符关闭会话。网络不发送SK、K或派生密钥。默认38580/读取0.2s/命令20s/间隔80ms，硬件字段不补齐截断，每完整字段独立反转，CT/K先拆分，33B签名消息沿用7B填充。

重新建钥由A协调，B请求A；暂停业务，重新握手、再次核对会话指纹，旧密钥销毁。若文件进行中则先完成或明确取消，不混用epoch。断线后旧会话不可恢复计数器。窗口只显示本地数据及对端认证消息，发送完成与接收确认分开。

交付：bin/LC01_Secure_Link_v0.exe、依赖DLL与许可、源码/build.cmd、中文README、协议/验证记录、独立ZIP与SHA256。exe内置--self-test/独立双进程测试工具，不能将软件密码测试称为硬件通过。真实COM操作只由用户显式连接触发。
